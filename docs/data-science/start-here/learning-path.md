# Learning Path: Interview Prep

> Docs: [Google: Rules of ML](https://developers.google.com/machine-learning/guides/rules-of-ml) · [scikit-learn user guide](https://scikit-learn.org/stable/user_guide.html)

Read the section in this order. Lifecycle first, because it's where projects fail and where interviewers probe; models second, because picking one is the easy part.

## Phases

| # | Phase | Pages | Practice | Time |
|---|---|---|---|---|
| 1 | **Frame** | [ML Project Lifecycle](../ml-lifecycle/index.md) · [Glossary](./glossary.md) (skim) | Lifecycle Q1–Q3 | 1 h |
| 2 | **Data** | [EDA](../ml-lifecycle/eda.md) · [Data Preprocessing](../ml-lifecycle/data-preprocessing.md) | EDA Q1–Q4 · Preprocessing Q1–Q4 | 2.5 h |
| 3 | **Features and training** | [Feature Engineering](../ml-lifecycle/feature-engineering.md) · [Model Training](../ml-lifecycle/model-training.md) | Features Q1–Q4 · Training Q1–Q4 | 2.5 h |
| 4 | **Production** | [Inference & Production](../ml-lifecycle/inference-and-production.md) | Production Q1–Q4 | 1 h |
| 5 | **Models** | [Supervised Learning](../supervised/index.md) · [Regression](../supervised/regression.md) · [Classification](../supervised/classification.md) · [Model Landscape](../landscape.md) (skim) | Each page's Q1–Q4 | 4 h |
| 6 | **Interview mode** | [Predictive Maintenance](../scenarios/predictive-maintenance.md): rehearse "How I'd explain" out loud | Follow-up Q1–Q3 · every ★★★ question again | 1.5 h |

## How to use a phase

| Step | Done when |
|---|---|
| Read the pages in the phase | You can say each page's Summary lines without looking |
| Study the figures | You can redraw each one from memory and say what the colours mean |
| Answer the Scenario questions out loud | You reach Prevent, with its trade-off, before opening the model answer |
| Quote the running example | You use its numbers (3% base rate, 0.24 → 0.46 PR-AUC) instead of generalities |

## Stars

| Stars | The question asks you to |
|---|---|
| ★ | Recall a fact or rule |
| ★★ | Apply it to the running example |
| ★★★ | Diagnose a failure or design a trade-off |

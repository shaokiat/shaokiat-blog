Kubernetes (CKAD)

New to Kubernetes? Start with the Learning Path, then follow Phase 1: Mental Model → Local Setup → Command Patterns. Every Lab has three tiers (🔴 Challenge, 🟡 Hints, 🟢 Guided), so pick your level.

Notes for Kubernetes interviews, using the CKAD curriculum as the syllabus. The exam is performance-based: you solve tasks in a live cluster with kubectl, so every reference page pairs concepts with commands and a hands-on lab that ends in a PASS/FAIL ✅ Check.

Interview prep path

Preparing for a hands-on interview? Follow the Learning Path: eight phases, about 30 hours, with a "Next in path →" link at the bottom of every page. Short on time: phases 1–4 and 8.

🔥 Core pages, the ones hands-on rounds test directly: Troubleshooting · Troubleshooting Drills · Deployments & Rollouts · Services & Ingress · Config & Secrets · Probes & Observability · Resources & Scaling · Scheduling & Shutdown · Container Images · Capstone · Mock Interview

Scenarios​

Interview-style systems that combine several reference pages. Explain each one end to end before the interview.

  • Capstone: Deploy an App: a timed 40-minute build, from Dockerfile to HPA and a rolled-back bad release
  • Mock Interview: four timed tasks with setup scripts and no visible hints
  • ML Model Serving: slow model load, startup probes, HPA, safe rollouts
  • Nightly Retraining Pipeline: CronJob, PVC for artifacts, concurrencyPolicy: Forbid
  • Zero-Downtime Release: rolling, canary and blue/green releases, rollback
  • Multi-Tenant Platform: namespaces, ResourceQuota, RBAC, NetworkPolicy
  • Troubleshooting Drills: Pending, CrashLoopBackOff, ImagePullBackOff, OOMKilled, Service with no endpoints

Fundamentals: Mental Model · Local Setup add-ons · Command Patterns · Architecture · kubectl Cheatsheet

Domain 1: Application Design and Build (20%)​

  • Define, build and modify container images → Container Images · imagePullPolicy · Lab 2-6
  • Choose the right workload resource: Deployment, DaemonSet, StatefulSet, Job, CronJob → Deployments & Rollouts · Jobs & CronJobs
  • Multi-container Pod patterns: init, sidecar, ambassador, adapter → Pods & Multi-Container · native sidecars
  • Persistent and ephemeral volumes → Storage · PV, PVC and StorageClass · access modes

Domain 2: Application Deployment (20%)​

  • Rolling updates and rollback → Deployments & Rollouts
  • Blue/green and canary with Kubernetes primitives → Release strategies · Lab 2-3 · Zero-Downtime Release
  • Deploy existing packages with Helm → Helm & Kustomize · Lab 7-2
  • Patch manifests per environment with Kustomize → Helm & Kustomize

Domain 3: Application Observability and Maintenance (15%)​

  • API deprecations → API groups and versions · finding deprecated APIs
  • Probes and health checks: startup, readiness, liveness → Probes & Observability
  • Built-in CLI monitoring: kubectl top, events, get -w → Built-in monitoring
  • Container logs → Probes & Observability
  • Debugging → Troubleshooting · Troubleshooting Drills

Domain 4: Application Environment, Configuration and Security (25%)​

  • Extend Kubernetes with CRDs and Operators → Security
  • Authentication, authorization (RBAC) and admission control → Request pipeline · RBAC · Pod Security Admission
  • Requests, limits and ResourceQuotas → Requests vs limits · LimitRange vs ResourceQuota · Scheduling & Shutdown
  • ConfigMaps and Secrets → Config & Secrets · injection methods
  • ServiceAccounts and SecurityContexts → ServiceAccounts · SecurityContext

Domain 5: Services and Networking (20%)​

  • NetworkPolicies → How selection works · peer selectors
  • Provide and troubleshoot access to applications via Services → Service types · the four ports
  • Expose applications with Ingress rules → Ingress vs Gateway API · Lab 2-5
